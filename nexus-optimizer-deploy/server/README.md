# Nexus licensing server

The static Nexus website cannot enforce keys by itself. This small server adds a
real customer portal, invite-only registration, license keys and the activation
API used by the desktop app.

It serves the existing site and the portal from one Node process. **No npm
dependencies** — Node 24+ is required because it uses the built-in `node:sqlite`.

## What it does

- Owner account `synx121` seeded from `OWNER_USERNAME`; **never listed** in
  customer tables.
- Owner password is **never hardcoded** and never written to the database in
  plain text. On first start the server prints a one-time setup link; the owner
  sets a password and only a scrypt hash is stored.
- Invite-only customer registration. Invite codes are generated by the owner,
  stored as hashes and shown only once.
- License keys generated by the owner, assignable to a customer email, with
  expiry and device limit. The owner can revoke every license/invite.
- Customer portal shows assigned keys, expiry, devices and downloads.
- Activation API for the desktop app: key + hardware ID → token; validate token
  on later starts.
- Sessions, CSRF protection, rate limits, scrypt password hashing, security
  headers, audit log.

## First start

```powershell
cd C:\Users\seenx\Desktop\website\server
node server.js
```

The included local `.env` is already configured for `OWNER_USERNAME=synx121`
and a scrypt owner hash, so the admin can log in through `/login` immediately.
The file is gitignored. If you start from `.env.example` instead, leave
`OWNER_PASSWORD_HASH` empty and the server prints a one-time setup link:

```text
Owner setup link (one-time): https://your-domain/admin/setup?token=...
```

Open that link once and set a long owner password. It expires after
`SETUP_TOKEN_MINUTES`. If the password is lost, or if you want to change the
preconfigured local password:

```powershell
node set-password.js
```

Only a scrypt hash is stored; no plaintext password is written to source code or
logs. `SESSION_SECRET` must be random and at least 32 characters; the local
`.env` already contains one, and `.env.example` explains how to generate it.

## URLs

| URL | Purpose |
| --- | --- |
| `/` | Marketing site |
| `/portal` | Customer dashboard (login required) |
| `/portal/register` | Invite-only registration |
| `/login` | Unified login (owner username or customer email) |
| `/admin` | Owner dashboard (not linked publicly; login at `/login`) |
| `/api/v1/activate` | Desktop app activation |
| `/api/v1/validate` | Desktop app validation |
| `/api/v1/deactivate` | Release a device token |

## API

### Activate

```http
POST /api/v1/activate
Content-Type: application/json

{"key":"NX-XXXX-XXXX-XXXX-XXXX","hwid":"stable-machine-id","version":"1.0.0"}
```

Response:

```json
{"ok":true,"token":"...","license":{"plan":"Pro","expires_at":"...","max_devices":1}}
```

### Validate

```http
POST /api/v1/validate
Content-Type: application/json

{"token":"...","hwid":"stable-machine-id"}
```

Response: `{"ok":true,"valid":true,"license":{...}}` or
`{"ok":true,"valid":false}`.

## Desktop app integration

The app reads the API base URL from, in order:

1. `NEXUS_LICENSE_API` environment variable,
2. `license-api.txt` next to `NexusOptimizer.exe`,
3. the URL saved during a previous activation.

It stores the activation token in
`%LOCALAPPDATA%\NexusOptimizer\license.json`. If the server is unreachable, a
cached activation is accepted for a short offline grace period; revoked or
expired licenses are rejected on the next online check.

Because the API URL is deployment-specific, it is **not hardcoded**. Put the
public server URL into `license-api.txt` before distributing the installer:

```text
https://your-domain.example
```

## Deployment (Render / VPS)

A `render.yaml` blueprint and a root `package.json` (`npm start`) are included.

1. Push the whole `website` folder to a Git repository and connect it to Render
   as a Blueprint. The blueprint creates a Node 24 web service with a persistent
   disk mounted at `server/data`.
2. Set `BASE_URL` to the public HTTPS URL if Render does not pick up
   `RENDER_EXTERNAL_URL` automatically. The server also falls back to
   `RENDER_EXTERNAL_URL`.
3. The blueprint supplies an owner password hash, so `/login` works after the
   first deploy. If you remove that variable, copy the one-time
   `/admin/setup?token=...` link from the service logs instead.
4. Put the service behind HTTPS. Cookies are marked `Secure` when `BASE_URL` is
   HTTPS.
5. Back up `nexus.db` regularly.
6. On your own VPS: run `npm start`, use a process manager (systemd/pm2) and keep
   `server/data` on persistent storage.

The static-only hosts (Netlify/Vercel static, GitHub Pages) cannot run this
server; the portal and activation API need Node.

## Security notes

- No plaintext owner password or license/invite keys in source code. The local
  `.env` and `render.yaml` contain only a scrypt owner hash.
- The preconfigured owner password is weak and has been shared in chat; rotate it
  with `node set-password.js` (and update the host secret/database) before
  selling access.
- Invite codes: hashed. License keys: stored in SQLite (needed to show them in
  the portal); protect the DB file and backups.
- The desktop gate is client-side. A determined user can patch an unsigned
  executable; the server-side device limit and revocation are the real control.
- This is an MVP. Add email delivery, password reset, 2FA and payment provider
  integration before selling at scale.
- Do not commit `server/.env`, `server/data/*.db*` or test databases.
